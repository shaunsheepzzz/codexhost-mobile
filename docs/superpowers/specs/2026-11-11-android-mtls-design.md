# Android 客户端证书支持：短设计（已确认）

## 目的

手机上的 Edge 已通过用户安装的客户端证书访问 SHAUNSHEEP。下一步让 fork 后的安卓 App 使用同一套系统证书能力，保留“客户端证书 + 网关 token”两层认证。

## 方案与取舍

推荐在现有 Kotlin/WebView 包装层增加 Android KeyChain 证书选择回调，保留现有前端、网关和协议。用户第一次连接时在系统对话框选择已安装的证书，应用取得系统授予的使用权限；不把客户端私钥打包到 APK。

独立重写原生网络层会扩大修改范围，目前不采用。仅改 JavaScript 无法实现 Android 系统客户端私钥选择，因此不采用。

没有上游 APK 签名私钥，不能覆盖更新手机上的原版。推荐 fork 使用自己的包名、名称和签名，让原版与测试版并存；不卸载原版、不迁移或删除聊天记录。测试版重新扫描原有网关二维码。

## 修改范围

1. Fork `unlgame/codexhost-mobile` 到已确认的 GitHub 用户 `shaunsheepzzz`，保持 Apache-2.0 许可和上游归属。
2. 沿用构建中固定版本的 PakePlus Android，使用可复现的补丁增加 `onReceivedClientCertRequest`。复用 KeyChain 系统选择器，按请求的服务器地址、端口、密钥类型和签发者筛选；在后台取得密钥及证书链，回到正确线程完成请求。取消、找不到密钥、Activity 关闭时安全结束请求。
3. 保留服务器证书验证；不新增跳过 TLS 校验、信任所有证书或默认为任意服务器使用私钥的逻辑。证书选择由 Android 系统授权完成。
4. 测试版采用独立应用 ID 和本地持久化签名；签名材料留本机，不提交仓库。构建与更新来源指向自己的 fork，避免安装上游不同签名的 APK。
5. 发布流程只构建改造版安卓 APK，不自动发布 npm 或 iOS。云端构建若使用，优先输出未签名产物，再在本机签名，避免将签名私钥交给 CI。

## 验证与完成条件

先为证书选择、用户取消、密钥缺失和生命周期结束写测试并观察失败，再实现处理逻辑；进行 Kotlin/安卓构建与签名验证。

在用户的 Redmi K90 Pro Max 上并行安装测试版，现场确认系统证书选择、HTTP 设备探测和 WSS 会话列表/恢复均可使用。验证没有证书和错误证书不能访问受保护入口。保留原网关 token，不发送测试聊天消息。

手机成功验收后，才单独收紧普通公网入口19443/19444；当前mTLS测试入口19445/19446不变。不得在旧入口仍开放时声称所有公网访问都已要求客户端证书。
